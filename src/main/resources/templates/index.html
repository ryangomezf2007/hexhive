CH1 · 01 — overview

What is CAN?

A messaging system invented by Bosch in 1986 to cut down on the spaghetti of wiring inside vehicles — now used far beyond cars.

1

One shared bus

Every device — engine, brakes, body, infotainment — taps into the same two wires instead of having its own dedicated line.

2

No central controller

Any device can transmit at any time. There's no master node deciding who talks when.

3

Messages, not addresses

Data is broadcast with an identifier. Every node hears it; each decides for itself whether it matters.

CH1 · 02 — advantages

Why it caught on

Six reasons CAN became the standard for in-vehicle and embedded communication.

01 — wiring

Less wiring

One shared pair of wires replaces dozens of point-to-point connections — lighter and cheaper.

02 — robustness

Very reliable

Built-in error detection and a signal that resists electrical noise.

03 — timing

Fast & timely

Priority-based access means urgent messages always get through first.

04 — topology

No single boss

Any device can transmit. No central point of failure to take the whole network down.

05 — filtering

Smart filtering

Devices only act on the message IDs that are relevant to them.

06 — cost

Low cost

Simple transceivers make CAN viable for mass-market hardware.

CH1 · 04 — message structure

Inside a frame

Every message on the bus is built from the same labeled fields, back to back.

SOF
1 bit
ID
11 bits
RTR
1 bit
CTRL
6 bits
DATA
0–64 bits
CRC
16 bits
ACK
2 bits
EOF
7 bits
SOF — marks the start of the message.
Identifier — what the message means, and its priority.
Control — how many data bytes follow.
Data — the actual payload, up to 8 bytes.
CRC — checksum so receivers can catch errors.
ACK — receivers confirm correct delivery.
EOF — marks the end of the message.
CH1 · 05 — bus arbitration

Who talks first?

When several devices transmit at once, they race bit by bit. A "0" always beats a "1" on the wire — no data is ever lost in the process.

CH1 · 06 — fault handling

Catching mistakes

CAN checks every message for five kinds of error, and quietly demotes any device that causes too many of them.

BIT ERROR

Signal on the wire doesn't match what was sent.

STUFF ERROR

Too many identical bits in a row.

CRC ERROR

Checksum doesn't match the message.

FORM ERROR

A fixed field has the wrong shape.

ACK ERROR

No device confirmed receipt.

ERROR ACTIVE

Normal mode. Everything works fine.

→

ERROR PASSIVE

Too many errors. Device gets quieter but keeps working.

→

BUS OFF

Way too many errors. Device disconnects to protect the network.
